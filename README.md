# WiFi 哨兵 · WiFiSentinel

原生 macOS 菜单栏工具，观察 Wi-Fi 关联、局域网及两个独立业务目标的响应；用户在应用内明确开启后，可按保护策略尝试恢复。菜单栏使用 20 pt 的“警觉双眼＋Wi-Fi”单色矢量图标，支持深浅色菜单栏与 Retina。

本仓库发布源码和必要项目文件，按 MIT 许可证提供。当前构建标识为 `0.1 / build 5.3`，没有发布安装包或公证二进制。

## 构建与离线检查

需要 macOS 13 或更新版本、带 Swift 5.9 或更新编译器的 Xcode Command Line Tools、Python 3 和 zsh。现有构建在 Apple Silicon Mac 上验证；Intel 尚未实机验证。项目使用 Apple 系统框架，没有 Swift Package 外部依赖。

```sh
/bin/zsh scripts/build.sh
WIFISENTINEL_OFFLINE_ONLY=1 /bin/zsh scripts/test.sh
```

候选包输出到 `build/candidates/rewrite5-exit0/WiFiSentinel.app`，不会自动替换运行中的应用。严格离线模式不创建网络监听器或访问真实网络。本次发布清理后的源码通过 **313 项严格离线用例**，其中新增 13 项隔离验证前置条件检查；离线结果不替代实际恢复验证。

直接由编译器生成的包可能只有临时签名。此稿不提供正式签名、公证安装包，也不建议绕过 macOS 安全检查。参见 [安装、卸载和回滚](docs/INSTALL.md)。

## 使用与恢复保护

- 首次启动先观察状态。菜单保留打开窗口、检测、暂停／继续、自动恢复开关和退出。
- 每次新进程默认关闭自动恢复。需要在应用中打开“允许本次启动自动恢复”并阅读、确认当前策略风险；恢复以前的设置不能代替本次确认。
- 每次自动关开须取得至少三轮、持续至少 120 秒的新鲜故障证据。单站失败、HTTP/DNS/TLS 错误、未知关联、睡眠和物理链路变化不能直接当作 Wi-Fi 故障。
- 可选“上网异常循环恢复”可能在局域网正常、上游或 VPN 异常时触发。启用它会增加中断正常无线连接的可能性，不能据此诊断 Wi-Fi 根因。
- 每次事务有界、串行，优先完成已发起的重新开启责任。关闭成功、开启成功或命令退出 0 均不等于联网恢复，仍须核实实际关联、本地和双业务响应。
- 两次连续自动验证失败后冷却 30 分钟清醒时间；睡眠不抵扣冷却。暂停、撤销许可和正常退出均保留安全清理流程。需要人工检查时，先在系统 Wi-Fi 菜单确认无线电与连接状态。

已保存网络重联属于独立、受限的验证路径；缺少目标、定位权限或本次验证证明时停止。无密码关联兼容性仍有 `-3900` 等已知失败，当前不能宣称已解决任意断线后的目标 SSID 恢复。不要用连续稳定观察代替这条恢复路径的验收。

## 数据与权限

本地设置、恢复状态和有界轮转日志位于 `~/Library/Application Support/WiFiSentinel/`。其中可能包含用户配置的 SSID、网关、接口及本地网络特征；诊断副本也可能包含这些内容。SSID 摘要不等于匿名化。

应用不读取 Wi-Fi 密码或私钥，不改变 VPN、DNS、路由或已保存网络配置。可选的当前网络读取需要用户通过标准定位授权流程允许；拒绝后不自动反复申请。默认业务探测联系 Apple 与 Cloudflare 的公开地址；它们及用户自定义目标能看到请求来源。参见 [隐私说明](docs/PRIVACY.md) 与 [依赖说明](THIRD_PARTY_NOTICES.md)。

## 已验证范围和已知限制

稳定性观察应绑定运行二进制哈希、实际进程和启动时间，分别报告墙钟时长、有效清醒观测时长、睡眠和缺口。没有记录应用动作的自然健康恢复不能追记为应用修复成功。没有异常或恢复尝试的窗口只支持该窗口稳定性，不证明故障注入恢复能力。

2026-10-20，在同一台 Apple Silicon Mac 上，此前冻结的图标版通过 **300 项严格离线测试**，并完成 **6 小时有效运行稳定性观察**：墙钟约 6 小时 41.6 秒，有效清醒观测约 6 小时 12.8 秒，约 28.8 秒启动核算时间未计入；没有观测到睡眠、采样缺口或采集读写错误。

该窗口记录 360 次新鲜探测：359 次健康、1 次单目标 DNS 失败，下一轮自然恢复。应用没有自动或手动恢复动作。因此这支持该观察窗口的运行稳定性，**不证明真实断网后的自动恢复能力**；SSID 重新关联及 `-3900` 兼容性仍未充分验证。

本次源码发布另外移除了隔离验证辅助模式的个人安装路径，改为按应用身份核对其他实例，并补测暂停、忙碌、清理责任、时间边界与异常快照。运行中的冻结版本没有因此被替换；这次清理后的新构建没有另外完成六小时实机观察。Intel、多设备及其他网络环境也未完成实机验证。

普通问题可通过 [GitHub Issues](https://github.com/ailifelab/WiFiSentinel/issues) 提交，先删除私人网络和诊断信息。安全问题请阅读 [SECURITY.md](SECURITY.md)；目前不承诺存在已启用的私密漏洞接收渠道，不要公开敏感细节。
