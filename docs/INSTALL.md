# 安装、更新、卸载与回滚

目前仅提供源码，没有已完成签名、公证和 Gatekeeper 验证的公开安装包。Developer ID 签名本身不等于已公证发行包；当前缺少公证认证，暂不提供下载。

构建目标最低为 macOS 13；当前检查环境是 Apple Silicon（arm64）和 macOS 27.0.1，较早系统及 Intel 尚未实机验证。自行构建需要 Swift 5.9 或更新编译器、Python 3 和 zsh。

## 第一次运行

1. 安装 Xcode Command Line Tools（需要时运行 `xcode-select --install`，由系统引导安装）。
2. 获取源码并构建：

   ```sh
   git clone https://github.com/ailifelab/WiFiSentinel.git
   cd WiFiSentinel
   /bin/zsh scripts/build.sh
   ```

3. 构建结果位于 `build/candidates/rewrite5-exit0/WiFiSentinel.app`。可以先直接打开；若打算长期使用，在正常退出后将它复制到 `~/Applications/` 等自己的应用目录，再从那里打开。
4. 在“状态与操作”查看结论。新进程默认关闭自动恢复；需要时由自己在应用内阅读风险并确认。

自行构建的应用没有正式发行签名或公证。遇到 macOS 安全提示时，请先核实来源，不要关闭系统安全检查。当前网络名称的读取可能需要定位授权，由你在系统弹窗中决定；拒绝后应用不会反复申请。

开发者可按[验证说明](VALIDATION.md)运行离线检查。普通使用不需要安装任何本机验证辅助程序或后台服务。

## 更新

1. 保留旧 `.app` 的完整副本，避免覆盖唯一可回滚版本。
2. 在旧应用菜单中正常退出。若提示 Wi-Fi 重新开启未确认，先到系统 Wi-Fi 菜单检查；不要强制结束正在恢复无线电开启状态的进程。
3. 确认旧应用已退出，再用新构建的候选替换自己的应用副本，并从预期目录打开。
4. 检查界面和检测结果。替换期间会有短暂监测中断；新启动仍需重新确认自动恢复。

## 回滚

正常退出当前应用，再恢复保留的旧 `.app` 并启动。不要手动编辑恢复事务或冷却文件来完成回滚。旧版本若提示状态不兼容或无法核实，先按提示人工检查。

## 卸载与本地数据

先正常退出，并确认没有未完成的 Wi-Fi 重新开启责任，再将应用移到废纸篓。

设置、异常日志及恢复策略状态位于 `~/Library/Application Support/WiFiSentinel/`。需要保留时可做一份私密备份；不再需要时，可在应用退出且没有未完成事务后删除此目录。删除会一并移除设置和冷却记录。定位等系统权限由 macOS 管理，不需要修改系统权限数据库。

## 正式 DMG 的安装方式

以下步骤只适用于未来在本仓库 Releases 中明确标注已签名、公证并完成系统验证的发行包。当前尚未发布这类附件，不要把本地准备包当成它。

1. 核对附件标注的架构与系统要求，并使用同页的 SHA-256 文件检查下载完整性。
2. 双击 DMG，将 `WiFiSentinel.app` 拖到同一窗口的 `Applications` 文件夹快捷方式中。更新前先正常退出旧版并留好回滚副本。
3. 从“应用程序”目录打开应用，再推出磁盘映像。macOS 可能显示标准的首次打开确认，由你决定是否打开；不要关闭 Gatekeeper 或跳过安全检查。
4. 首次启动先观察状态，自动恢复默认关闭。需要恢复操作时在应用内确认风险。
5. 读取当前 Wi-Fi 名称时，定位授权由你在系统弹窗中决定。Developer ID 签名和公证不会自动授予定位、网络控制、辅助功能或管理员权限；应用不安装特权后台服务。
